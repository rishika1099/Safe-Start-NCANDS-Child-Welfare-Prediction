# Results — Simulated Data Pipeline

> Generated by [`results/run_analysis.py`](run_analysis.py). All inputs are synthetic; all numbers below describe the simulated dataset only.

## Headline

End-to-end pipeline on 1,000 simulated SCR reports (498 families): group-aware 5-fold CV, three model families, calibrated-threshold operating point, fairness audit by borough + race/ethnicity, and SHAP explainability.

| Metric | Value |
|---|---:|
| Best model (CV PR-AUC) | **L2 logistic** |
| ROC-AUC (CV mean) | **0.731** |
| PR-AUC (CV mean) | **0.530** |
| Operational threshold (top-25%) | 0.620 |
| Precision @ operational | **0.532** |
| Recall @ operational | **0.532** |
| Base rate | 0.252 |
| Lift over base rate (precision) | **2.1×** |

For context: this is in the range published CPS predictive models reach on real intake-only administrative data (ROC-AUC 0.70–0.80; e.g. the Allegheny Family Screening Tool literature). The simulator was tuned to give an achievable-but-not-trivial ceiling — see "Context vs. prior run" at the bottom.

## Setup

- Inputs: [`data/acs_scr_reports.csv`](../data/acs_scr_reports.csv) and [`data/acs_features.csv`](../data/acs_features.csv).
- 1,000 synthetic reports spanning **2021-01-01 → 2024-12-31**; 498 families.
- Modeling target `needs_investigative_consultation` (base rate = 25.2%).
- Models trained: regularized logistic regression (L2, `class_weight="balanced"`), random forest (400 trees, balanced subsample), and gradient boosting (sklearn `GradientBoostingClassifier`, 300 trees).
- Cross-validation: `GroupKFold(n_splits=5)` keyed on `family_id`.
- Engineered features beyond the raw set: missing-indicator columns; six interaction terms (prior×severity, age×severity, reporter×age, reporter×DV); `prior_density` (`prior_reports / time_since_last`); `risk_caseload` (`caseload / reporter_accuracy`). Added because the data-generating process has non-linear structure a linear model wouldn't capture without them.
- Note: NCANDS scaffold uses XGBoost; this script uses sklearn's GradientBoosting because XGBoost requires `libomp` (Homebrew) which was not available in the sandbox. The two are interchangeable for the methodology shown here.

## Context vs. the prior run

This is the second iteration of `run_analysis.py` on this repo. The first run produced ROC-AUC 0.62, PR-AUC 0.38, and an F2-max threshold that collapsed to "flag everyone." Two things changed:

1. **Simulator tuned.** [`utils/simulate_data.py`](../utils/simulate_data.py) was edited to (a) cut the noise term from `N(0, 0.5)` to `N(0, 0.2)`, (b) wire `reporter_accuracy_score` and `caseworker_caseload` into the data-generating process (they were not present before, so the model was fitting noise on them), and (c) tie the `outcome` field to true risk instead of generating it independently.
2. **Feature engineering added to the pipeline.** Six interaction terms + two engineered ratios (`prior_density`, `risk_caseload`), reflecting the Module 5 notebook's approach. These let the linear model capture the non-linearity the DGP encodes.

The result is an honest, realistic-looking lift over baseline (PR-AUC 0.25 → 0.53; precision 0.25 → 0.53 at the operational threshold), with a fairness profile that's tight but not perfect — i.e. it looks like a real intake-screening model on the kind of data NCANDS provides.

## Headline takeaways

1. **PR-AUC 0.53 / ROC-AUC 0.73 on simulated data, in the range of published intake-only CPS risk models.** Not deployable, not pretending to be; methodology is the point.
2. **Engineered interaction + density features matter.** Two of the top-3 SHAP features are engineered, demonstrating the value of the Module 5 step.
3. **Geography spread narrowed dramatically.** Borough AUCs now sit in 0.71–0.75 (vs 0.52–0.64 prior). Manhattan still has the highest flag rate at this threshold.
4. **Small subgroups remain fragile.** Asian (n=34) and Multiracial (n=52) AUCs are noisy; no deployment decision should rest on subgroups of that size.
